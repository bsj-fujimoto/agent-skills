# レポートの型(障害分析 / レビュー / 移行プラン / 改善ガイド / スコア採点)

## 障害分析 (incident-analysis.html) — 顧客説明用
1. エグゼクティブサマリ(1段落で結論。重大障害が同一根本要因に収束するなら明言)。
2. 障害の全体傾向(件数・重大度・時系列の山)。
3. 根本要因マップ(archify dataflow: 障害 → 根本原因 → 対策 を行ごとに)。
4. 根本要因を5前後のテーマで(各: **該当障害# / 調査での裏付け / 根本原因 / あるべき姿** の表)。
5. 改善ロードマップ(フェーズ別)。
6. **期待効果を3視点で**: ①エンドユーザー(障害減・速度・不具合減・無停止・安全)②サービス提供者(問い合わせ/補填減・機会損失=売上保全・コスト最適化・信用)③保守ベンダー(緊急対応激減・計画化・調査高速化・脱属人)。
7. 進め方の提案(効率化を先に、増強は必要分だけ)。

## Well-Architected レビュー (review.html)
6本柱(運用/セキュリティ/信頼性/性能/コスト/持続可能性)を ◎○△× で評価 → 各柱で「良い点 / 要改善」。
良い点も必ず挙げる(GuardDuty/WAF/CloudTrail/Config、読み書き分離、Graviton/gp3 等)。

## 移行プラン (roadmap.html)
- Phase 0(即時・無停止): 棚卸し/SG是正/暗号化/証明書/タグ。
- Phase 1.5(**最優先・低コスト高効果**): DBクエリ/インデックス/ロック是正。→ 実測。
- Phase 2(実測後に必要分だけ): RDS Proxy/Reader増設/Redis・NAT・バッチ冗長化。
- Phase 3(中期): 専用VPC移行/IaC/段階リリース/ライトサイジング/観測性。
- 指針: 「効率化 → 実測 → 必要分だけ増強」。増設を先にするとコストの割に頭打ち。
- **索引追加の注意**: 大規模テーブルは無停止でなく計画メンテ相当(構築負荷/レプリカ遅延/メタデータロック/書込コスト増)。スナップショット→クローンで計測→低トラフィック枠でオンラインDDL→巨大表は pt-online-schema-change/gh-ost。

## 改善ガイド (improvement-guide.html) — 本スキルの目玉
全ドキュメントの要改善点を**集約し「直す順序」**にする(単なる抽出にしない)。
- 冒頭に **スコアダッシュボード**(`templates/scorecard.html`)。
- 順序の3原則: ①止血(信用/法/金銭)最優先 ②「測れる化→効率化→増強」 ③無停止/低リスク先。
- 推奨STEP順(プロジェクトに合わせ調整):
  - STEP0 止血・セキュリティ(鍵ローテ/不正対応/暗号化/SSH閉塞/棚卸し)
  - STEP1 可観測性(監視穴・スロークエリ可視化・根因追跡の土台)
  - STEP2 DB効率化(索引/ロックのチャンク化/全件クエリ是正/生SQL) ← 本丸・高効果
  - STEP3 実測後に必要分だけ増強・可用性(RDS Proxy/Reader/Redis/NAT/バッチ冗長)
  - STEP4 配信・バッチ再設計(冪等/緊急停止/レート/キュー駆動)
  - STEP5 リリース/変更管理(検証環境/IaC/段階リリース/ブランチ運用)
  - STEP6 コード健全化・認証近代化(SHA1→bcrypt/トークン保護/TLS/デッドコード削除)
  - STEP7 アプリ品質(テスト/DI/更新/API版統合/DB明文化)
- 各STEP: 目的 / やること(具体・元ページとIDリンク) / なぜこの順番 / 完了の目安。
- 末尾に **優先度マトリクス表**(STEP×領域×項目×重大度×工数×ユーザー影響)と **クイックスタート(最初の2週間TOP5)**。

## スコア採点ルーブリック(ダッシュボード)
観点(例): セキュリティ / DB・パフォーマンス / 信頼性・可用性 / 運用・変更管理 / コスト最適化 / コード品質・保守性。
- 各観点を 0–100 で相対評価(**所見ベースの目安・絶対指標ではない**と明記)。帯: <40 危機(E,#f2545b) / 40-54 要改善(D,#f5924b) / 55-69 注意(C,#e8b93a) / 70+ 良好(B・A,#35c07a)。
- 総合 = ユーザー影響で**重み付け平均**(例 セキュリティ/DB各25%・可用性20%・運用/コスト/保守各10%)。conic-gradient の % に総合値を入れる。
- 配色は dataviz 準拠: 状態カラーは**値・グレード・凡例ラベルを必ず併記**(色だけに依存しない)。赤→橙→黄→緑の知覚順。
- 「改善(STEP0〜2)実施で総合を C〜B 帯へ引き上げ可能」「改善後に再スコアリングで効果可視化」を添える。
