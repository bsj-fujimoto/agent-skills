# eli5-form

論点を並べた HTML を作り、**読む人がその場で回答でき、疑問はその場で Claude に聞ける**
ようにする。回答は HTML 内に Markdown 表示で戻り、localStorage に残る。

通常の `eli5`（説明するだけ）との違いは **回答を受け取るのが目的**である点。

## 作る前に決めること

1. **何件の論点を載せるか** — 多いときは観点ごとにグルーピングする
2. **各項目に AI 推奨を出せるか** — 資料・コード・過去のやり取りから根拠を示せるなら必ず付ける
3. **出典** — 「ここのことです」が分かるよう、該当ファイル・ページ番号・図を添える

## 必須要件

### 各項目に入れるもの

- **番号と短いタイトル**（`#3 Azureのレート上限` のように参照しやすく）
- **何が困るのかを一言で** — 決まらないと何が進まないか
- **出典へのリンク** — ファイルパス、仕様書のページ番号、該当キャプチャ画像
- **図** — 文章で伝わりにくい対比・流れはインライン SVG で描く
- **選択肢**（ラジオ）＋ **自由記述**（textarea）
- **AI推奨** — 根拠付きで。`推奨` バッジを付けて選択肢に併記する
- **Claude への質問欄** — 「これってなんのこと？」にその場で答えられるように

### 全体に入れるもの

- 冒頭に **進捗カウンタ**（`3 / 32 件 回答済み`）と「次の未回答へ」ジャンプ
- **localStorage への自動保存**（閉じても消えない）＋ 全消去ボタン
- **回答の書き出し** — コピーできるテキスト。そのまま貼り付けて記録に使える
- **ファイルへの保存** — localStorage はブラウザを消すと失われる。
  決定事項として残すなら `saveToFile('<name>')` でサーバーに書かせる
  （`server.py --save-dir <dir>`）。出るのは**凍結版 HTML 1枚**で、
  回答 JSON は `<script type="application/json" id="answers">` に**埋め込まれる**。
  HTML だけ配ればデータも一緒に渡り、ページ上のボタンで JSON を取り出せる
- **通知スタック**（右側・スクロール追従）— 回答が届いたら積み上げ、クリックで該当項目へ飛ぶ

## Claude チャットの組み込み

`scripts/askclaude/server.py` をプロジェクトにコピーして使う
（このスキルの `scripts/server.py` が原本）。

**リポジトリのルートから起動する。** `--dir` は静的配信のルートを決めるだけで、
`claude` を動かす作業ディレクトリは**起動時の cwd から見た git トップレベル**
（取れなければ cwd）になる。スクラッチパッドに `cd` してから起動すると、
`claude` がリポジトリの外で走り、プロジェクトの `CLAUDE.md` やメモリを読まない。
フォークしたセッションのログも、スクラッチパッド由来のプロジェクトに溜まる。

```bash
cd <リポジトリ>                       # ← ここが claude の作業ディレクトリになる
python3 scripts/askclaude/server.py --ensure --port 8899 --session <session-id> \
  --dir <htmlのある場所> --save-dir <回答の保存先>
```

`--save-dir` を付けると `/save` が有効になり、ページの「決定として保存」ボタンから
回答を JSON で書き出せる。付けないと保存は拒否される。

**ページ配信と API を同じポートに載せること。** 別ポートにすると dev container の
ポート転送が 1 つでは足りず、ブラウザ（ホスト側）から API に届かない。
HTML は `http://localhost:8899/<ファイル名>` で開く。`file://` では動かない。

### 立てっぱなしにしない

セッションごとにサーバーを立てると、どれが生きているか分からないまま残る。
次の 3 つで片付く。

| 指定 | 何をするか |
|---|---|
| `--ensure` | 同じセッションのサーバーが既に居ればその URL を出して終わる。居なければ起動する。**起動はいつもこれで書く**（二重起動しない） |
| `--status` | 動いているサーバーを一覧する（セッション ID・最終操作からの経過・配信ルート）。覗いても寿命は延びない |
| `--idle-timeout` | やりとりが無いまま経つと自分で終了する。既定 1800 秒、`0` で無効 |

**ポートが埋まっていたら自動で次の空きへ上がる**（上に 20 個まで）。ずらしたときは
起動案内に警告が出る。dev container でポート転送を設定しているなら転送先も変える。

**ページは開いている間だけサーバーを生かす。** 60 秒ごとに `/health?ping=1` を打つ
心拍を入れておくと、タブを閉じた時点で打たれなくなり、時間切れで勝手に終了する。
`?ping=1` が無い `/health` は寿命を延ばさない（`--status` が延命してしまわないため）。

```js
function beat(){ if(!document.hidden) fetch('/health?ping=1',{cache:'no-store'}).catch(()=>{}); }
setInterval(beat, 60000);
document.addEventListener('visibilitychange', ()=>{ if(!document.hidden) beat(); });
```

**ページからサーバーを自動起動することはできない**（ブラウザにプロセス起動の手段が
無い。そもそもページ自体をサーバーが配っているので、落ちていれば開けない）。
届かなかったときは、`--ensure` 付きの復帰コマンドをそのまま打てる形で画面に出す。

### セッションIDの渡し方

**いま作業しているセッションの ID** を埋め込む。そうすると Claude は資料を作った
文脈をそのまま持っているので「#3 ってなんのこと？」に答えられる。

`--fork-session` が付くため、**元のセッションには書き込まれない**（対話画面の
`/btw` と同じ考え方）。付けない場合は元セッションに ~27KB 書き込まれる。

### HTML 側

`fetch('/ask', {method:'POST', body:JSON.stringify({prompt, session:SID})})` で投げる。
プロンプトには**項目の番号とタイトルを添える**と、文脈が絞れて回答が良くなる。

```js
const prompt = '【確認シート 項目 #'+i+'：'+T[i-1]+'】\n'+t
  + '\n\n（この項目について、シートの読者に向けて簡潔に答えてください）';
```

**返ってくる形は `{answer, session}`。`ok` も `text` も無い。**

| | 形 |
|---|---|
| 成功 | HTTP 200 ＋ `{"answer": "…", "session": "…"}` |
| 失敗 | 非 200 ＋ `{"error": "…"}`（タイムアウトは 504、claude が無ければ 500） |

`j.ok` を見ると `undefined` なので必ず失敗側に落ち、`j.error` も無いため
「エラー: 不明」とだけ出て、**届いていた回答を捨てる**。実際に踏んだ。

```js
const j = await r.json().catch(()=>({}));
const good = r.ok && typeof j.answer === 'string';
const ans = good ? (j.answer.trim() || '(空の回答)')
                 : ('エラー: ' + (j.error || ('HTTP ' + r.status)));
notify(i, good ? 'done' : 'err');
```

## 実装の注意（過去に踏んだもの）

実装コードは `scripts/form-parts.js` と `scripts/form-parts.css` にある。そのまま使う。

- **回答は Markdown でレンダリングする。** 生テキストだと表やコードが読めない。
  `md()` を使う（外部ライブラリは読み込まない。`file://` でも動くように）
- **通知は snackbar にしない。** 消えると見逃す。右側にスクロール追従で
  **積み上げたまま残し**、× で明示的に消す
- **通知の文字色は明示する。** `<button>` の既定色のままだと文字が見えない
- **待機中の「...」でレイアウトを動かさない。** `content` を差し替えると幅が変わる。
  `content:'...'` を固定して `clip-path` で隠す。**0個の状態は作らない**（1,2,3,1 と回す）
- **待機中の通知には × を出さない。** 回答が届いてから出す
- **多重送信を止める。** 回答待ちの間は送信ボタンを無効化する
- **質問欄は `<textarea>` にする。`<input>` は改行できない。** 質問は複数行になる
- **日本語入力の変換確定 Enter で送信しない。** `event.isComposing`（と古い環境向けに
  `keyCode === 229`）で変換中を判定して弾く。IME によっては `isComposing` が
  立たない組み合わせがあるので、`compositionstart` / `compositionend` も併用する。
  **`bindAsk()` を使えばこの2つは解決する**（`Enter` 改行 / `Ctrl`・`Cmd`+`Enter` 送信）
- **送信キーを画面に書く。** `Enter` で送れると思っている人がいるため、
  書かないと「送れない」と受け取られる
- **`/ask` の戻りは `answer` を見る。** `ok` / `text` ではない（上の表）。
  形を推測すると、届いた回答を黙って捨てて「エラー: 不明」になる
- **届かなかったときは復帰コマンドを出す。** 「サーバーが動いているか確認して」では
  何をすればいいか分からない。サーバーは放置で自動終了するので、届かない原因は
  たいていそれ。`--ensure` 付きの 1 行をそのまま打てる形で画面に出す

## セキュリティ

サーバーは以下を必ず守る（`scripts/server.py` は対応済み）。

- `127.0.0.1` のみで待ち受ける
- セッションIDは `^[0-9a-f-]{36}$` で検証してからコマンドに渡す
- プロンプトは **argv で渡す**（`shell=True` を使わない）
- 長さ上限 4000 文字・タイムアウト 180 秒

## 出力ルール

- **ローカルファイルとして生成する。** Artifact として公開しない
- 保存先はスクラッチパッドディレクトリ（ユーザー指定があればそちら）
- ファイル名は `eli5-<トピックのスラッグ>.html`
- 生成したらサーバーを起動し、`http://localhost:<port>/<ファイル名>` を開く
- 最後に**絶対パスと URL** をユーザーに伝える

## 回答を受け取ったあと

回答はシートに残すだけでなく、**決定として文書に記録する**。

**まず `saveToFile()` でファイルに落とす。** localStorage のままだと、
ブラウザの履歴を消した時点で「何をどう決めたか」の一次情報が消える。
保存した HTML は回答の原本として、文書の側から参照できる場所に置く。

**HTML 1枚で完結させる。** 論点の本文・出典・図・AI の見立て・回答・Claude との
やり取りが、見た目のまま入っている。回答 JSON も埋め込んであるので、
集計に使いたければページ上のボタンか
`JSON.parse(document.getElementById('answers').textContent)` で取り出せる。

- 決定が設計を左右するものなら **ADR** に起こす
- 元の要件・設計文書の該当箇所を更新し、TBD を消す
- 「未回答」と書かれた章が残っていないか確認する（実態と乖離しやすい）
